# 사내 통합 이메일 시스템 PRD (Product Requirements Document)

- 작성일: 2026-07-07
- 문서 상태: Draft v1.0 (일정/예산 미정 상태에서 요구사항 확정용)

---

## 1. 배경 및 문제 정의

우리 회사는 보안시설로서 **외부망/내부망(업무망) 분리 환경**을 운영 중이다. 현재 직원들이 사용하는 이메일 시스템은 다음과 같은 문제를 안고 있다.

| 구분 | 현재 문제 |
|---|---|
| 망간 파일 전송 | 외부망 메일로 받은 첨부파일을 내부망으로 옮기려면 이메일과 **별도의 전송 프로그램**을 거쳐야 함 |
| 승인 절차 | 상사 승인 + 보안담당자 승인의 2단계 절차가 있으나, 도구가 분리되어 있어 번거로움 |
| 사유 기재 | 전송 사유 기재가 필수이나 **정해진 서식/검증이 없어** 공란(공백문자)으로 제출해도 통과됨 → 실효성 없는 형식적 절차로 인식 |
| 인증 | 망간 전송 시 **개인 OTP 재로그인**이 필요해 번거로움 |
| 검색/정리 | 메일 검색과 폴더 정리가 불편함 |
| 협업 | 메일 기반 협업(코멘트, 담당자 지정 등) 기능 부재 |
| 중요도 | 메일별 중요도 구분 기능 없음 |

**핵심 문제 정의**: *"보안 규정을 지키면서도, 직원들이 망간 자료 전송·검색·협업을 이메일 하나에서 끊김 없이 처리할 수 있는 사내 자체 이메일 시스템이 없다."*

---

## 2. 목적 (Goals)

1. 외부망→내부망 첨부파일 전송을 이메일 내에서 원스톱으로 처리하여 별도 프로그램 이용 절차를 제거한다.
2. 보안 절차(승인, 인증)는 유지하되 **실효성 있는 형태로 재설계**하고, 사용자 편의를 개선한다.
3. 검색·정리·협업 기능을 추가해 업무 생산성을 높인다.
4. 사내 폐쇄망에 자체 구축 가능한 온프레미스 시스템으로 구현한다.

### 성공 지표 (제안, 추후 확정 필요)
- 망간 전송 1건 처리에 필요한 화면 전환/프로그램 수: 현재 N개 → 1개(이메일 내 완결)
- 망간 전송 승인 소요 시간 단축률
- 직원 만족도 설문 점수 개선
- 메일 검색으로 원하는 정보를 찾는 데 걸리는 시간 단축

---

## 3. 타겟 사용자 및 규모

- **사용자**: 사내 전 직원 (동시 사용자 약 50~200명 규모의 조직)
- **역할 구분**:
  - 일반 사용자(발신/수신, 망간 전송 신청자)
  - 승인자(상사) — 소속 부서 결재 라인
  - 보안담당자 — 망간 전송 최종 승인
  - 시스템 관리자 — 계정/정책/로그 관리

---

## 4. 범위 (Scope)

### In Scope
- 완전 신규 자체 이메일 시스템 (발신/수신/저장 전 영역 자체 구축, 기존 이메일 시스템 대체)
- 외부망-내부망 간 첨부파일 전송 신청·승인·전송 요청 기능의 이메일 내 통합
- 사내 SSO/사원증 인증 + OTP 연동 로그인
- 통합검색(첨부파일 내용 포함), 사용자 지정 폴더/라벨, 고급 필터, 자동 아카이빙
- 메일 내 코멘트/멘션 태그 기능
- 수신자가 직접 설정하는 중요도 태깅
- 온프레미스(사내 폐쇄망) 배포

### Out of Scope (v1 기준)
- 기존 이메일 시스템의 과거 데이터(받은편지함, 주소록 등) 마이그레이션 — **이관 불필요, 완전 신규 시작**
- 외부 클라우드 인프라 사용
- 발신자가 사전에 중요도를 지정하는 기능 (수신자 지정 방식만 채택)
- 업무 위임/담당자 자동 배정 등 고급 협업 기능(코멘트/멘션 외) — 추후 로드맵 후보

## 5. 핵심 기능 요구사항

### 5.1 망간(외부망→내부망) 첨부파일 전송 — 최우선 기능

**As-Is**: 별도 전송 프로그램 접속 → OTP 재로그인 → 형식 없는 사유란 입력(사실상 무의미) → 상사 승인 → 보안담당자 승인 → 전송

**To-Be**:
1. 사용자는 이메일 화면에서 첨부파일을 선택하고 **"내부망 전송 요청"** 버튼 클릭
2. 별도 프로그램/재로그인 없이 동일 세션 내에서 신청서(전송 요청) 생성
3. 승인은 기존과 동일하게 **상사 승인 → 보안담당자 승인 2단계** 유지
4. 승인/반려, 전송 진행 상태를 메일 내 타임라인 형태로 실시간 확인 가능
5. 승인 완료 시 시스템이 자동으로 보안검사(바이러스/DLP 등 기존 보안 정책 연동) 후 내부망으로 전송

> **주의(리스크)**: 현재 요구사항은 "전송 사유 기재란 제거"이나, 망간 자료 반출입은 보안감사·규정 준수 대상인 경우가 많다. 사유 필드를 완전히 없애는 것이 내부 보안 지침/감사 요건에 저촉되지 않는지 **보안담당 부서 확인이 선행**되어야 한다. (자세한 내용은 9. 리스크 항목 참고)

### 5.2 인증(로그인/OTP) 통합

- 사내 SSO(사원증 등)와 OTP를 **1회 인증으로 연동**, 이메일 로그인과 별도의 재로그인 절차 제거
- 망간 전송 등 민감 동작에 대해서는 세션 내 기 인증된 정보를 재사용하되, 시스템 정책상 필요한 재인증 조건은 보안팀과 별도 협의

### 5.3 검색 및 정리

- 첨부파일(문서/PDF 등) **본문 내용까지 포함하는 통합검색**
- 사용자 지정 **폴더/라벨 체계** (다중 라벨 지원)
- **고급 필터**: 발신자, 기간, 첨부파일 유무 등 다중 조건 조합 검색
- **자동 아카이빙/보관주기 정책**: 설정된 기간 경과 메일 자동 이동(보관함), 조직 차원의 보관 정책 설정 가능

### 5.4 협업 기능

- 메일 내 **코멘트/멘션(@태그)** 기능: 메일을 전달하지 않고도 특정 동료를 멘션하여 해당 메일에 대해 논의 가능
- 코멘트는 메일 원문과 분리되어 표시(스레드형 사이드 패널 등), 외부 발신자에게는 노출되지 않음

### 5.5 중요도 태깅

- **수신자가 메일을 받은 후 직접 분류/태그**(예: 높음/보통/낮음 또는 커스텀 태그)
- 태그는 개인별로 독립 적용(발신자 지정 없음), 태그 기준 정렬/필터 가능

## 6. 비기능 요구사항

| 항목 | 요구사항 |
|---|---|
| 배포 환경 | 사내 폐쇄망(On-premise) 자체 서버, 외부 클라우드 사용 불가 |
| 보안 | 기존 망분리 정책, 보안검사(바이러스/DLP 등) 정책과 연동 유지 |
| 인증 | 사내 SSO/사원증 + OTP 연동 |
| 가용성/성능 | 동시 사용자 50~200명 기준 응답속도 및 안정성 확보 (구체 SLA는 후속 협의) |
| 로그/감사 | 망간 전송 신청·승인·전송 전 과정에 대한 감사로그 기록 필수 (사유 필드 제거 여부와 별개로 유지) |
| 데이터 이관 | 불필요 — 완전 신규 시작 |

## 7. 사용자 시나리오 (예시)

**시나리오: 외부망에서 받은 문서를 내부망으로 전송**
1. 직원 A가 외부 메일로 첨부파일이 있는 메일을 수신
2. 첨부파일 옆 "내부망 전송 요청" 클릭
3. 재로그인 없이 전송 요청 생성 → 상사에게 승인 알림 전송
4. 상사 승인 → 보안담당자에게 승인 알림 전송
5. 보안담당자 승인 → 시스템이 보안검사 수행 후 내부망 계정으로 자동 전송
6. A는 메일 화면에서 전송 상태(대기/승인/전송완료)를 실시간 확인

## 9. 리스크 및 오픈 이슈

1. **[중요] 전송 사유 기재 제거의 컴플라이언스 리스크**: 망간 자료 전송은 보안 감사·정보보안 지침 대상인 경우가 일반적이다. 사유란을 완전히 삭제하기 전, 보안담당 부서/감사 기준과의 충돌 여부를 확인 필요. 대안으로 "사유 기재는 유지하되 드롭다운 코드화 + 최소 글자수 검증"으로 형식적 절차 문제만 해결하는 절충안도 고려 가능.
2. **OTP-SSO 통합 인증의 보안 영향도 검토**: 재인증 절차 축소가 보안정책상 허용 범위인지 보안팀 승인 필요.
3. **자체 이메일 서버 구축 범위**: 발신/수신/저장까지 완전 자체 구축은 개발 범위와 리스크가 크므로, 오픈소스 메일 서버(예: 자체 SMTP/IMAP 스택) 활용 여부는 기술 검토 단계에서 결정 필요.
4. **일정/예산 미정**: 개발 주체(사내 vs SI 발주) 및 일정에 따라 우선순위(MVP 범위)가 달라질 수 있음.
